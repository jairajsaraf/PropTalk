# PropTalk — Project Context

## What this is
A Streamlit demo: plain-English questions about property data → an LLM writes SQL (SQLite) or pandas code → it is validated and executed → results render as a Plotly chart and a table. All data is synthetic.

## Architecture
- Two query engines, chosen in the sidebar, over the same synthetic CSVs in `sample_data/` (generated by `generate_sample_data.py`, gitignored).
- **SQL**: `sql_guard.py` (text-level: SELECT-only, no `;`, keyword blocklist, table whitelist, LIMIT cap) → `sqlite_backend.py` (in-memory SQLite: authorizer allowlist, `PRAGMA query_only`, progress-handler time budget, value-size limit, `fetchmany(MAX_ROWS)`). The engine controls must hold even when the guard is bypassed; `tests/test_sqlite_backend.py` checks this.
- **pandas**: `csv_backend.py` (regex blocklist → worker process on a pickled copy, builtin allowlist, timeout). It is not a sandbox. Its behavior is versioned in `EXEC_CONTRACT`; bump the version when the executor's behavior changes, so saved eval reports still re-score under their own contract.
- Decisions are recorded in `docs/adr/`.

## Confidentiality rules
- Code is public on GitHub. Data is synthetic only.
- Never add real data, real table/database/server names, or institution, vendor or employer references.
- API keys live in `.env` only (gitignored).

## LLM API
- Any OpenAI-compatible endpoint: `LLM_API_BASE` (default `https://generativelanguage.googleapis.com/v1beta/openai`), `LLM_API_KEY`, `LLM_MODEL` (default `gemini-3.5-flash-lite`).
- Uses `requests.post` directly, not an SDK, with `"stream": false` and temperature 0.

## Evaluation
- `evals/`: case files (`questions.jsonl`, `adversarial.jsonl`; their hashes are recorded in the preregistrations), `PREREGISTRATION*.md`, `run_eval.py`, `scoring.py`, `publish.py`. Reports are in `results/`.
- Never edit a committed report or preregistration after its live run. A new run needs a new preregistration, committed first, and a new report path.
- Numbers in the README results block come only from `results/metrics.json` via `python -m evals.publish --write`. Never hand-edit that block.
- A live run calls a rate-limited API: ask before running one.

## Key files
- `app.py` — Streamlit UI
- `llm.py`, `prompts.py` — LLM call, response parsing, system prompts
- `sql_guard.py`, `sqlite_backend.py` — SQL validation and the locked-down engine
- `csv_backend.py` — CSV loading, pandas validation and execution
- `config.py` — table registry
- `chart_builder.py` — Plotly charts from the LLM's chart_config
- `generate_sample_data.py` — synthetic data generator (committed)

## Commands
- `python generate_sample_data.py` — generate the synthetic CSVs
- `streamlit run app.py` — run the app (needs `LLM_API_KEY` in `.env`)
- `python -m pytest -q` — offline tests (about 10 minutes on Windows, where pandas workers start with `spawn`)
- `python -m ruff check .`
- `python -m evals.publish --check` / `--write` — verify or regenerate metrics and the README block
- `make ci` / `make reproduce` — all of the above (Linux and CI)

## Coding conventions
- Type hints on all function signatures
- `@st.cache_data` for data loading, `@st.cache_resource` for connections
- Secrets come from `.env` via `python-dotenv`, never hardcoded
- Commit messages: imperative mood, concise, no attribution trailers
